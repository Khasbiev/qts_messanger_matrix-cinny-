# PWA Icon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real `>`-glyph icon files exist at the two sizes `manifest.json` already declares, and the browser tab/bookmark/PWA-install icon show them instead of a placeholder — per `docs/superpowers/specs/2026-09-06-pwa-icon-design.md`.

**Architecture:** A single task. Render a small local HTML page (dark background, centered teal `>` glyph, matching `Auth/LoginScreen.jsx`'s existing brand treatment) via a browser screenshot at each of the two exact target resolutions the manifest already declares, saving the results as `client/public/icon-192.png` and `client/public/icon-512.png`. Add the two missing `<link>` tags to `index.html`.

**Tech Stack:** Plain HTML/CSS + a browser screenshot tool (Playwright MCP) — no new npm dependency, no image-editing tool.

## Global Constraints

- No maskable-icon variant, no legacy `favicon.ico`, no icon size beyond the two `manifest.json` already declares, no changes to `manifest.json` itself — all explicitly out of scope.
- Icon background is opaque `#0C0C0E` (this app's `--bg-primary`/`theme_color`), glyph color `#00E5B0` (this app's `--accent-teal`) — exact values, not approximations.
- No automated test framework exists in `client/` — verification is manual (load the app, check the tab icon and that the two files 200 instead of 404).

---

### Task 1: Generate the two icon files and link them from `index.html`

**Files:**
- Create (temporary, deleted before commit): a scratch HTML file used only to render the icon for screenshotting.
- Create: `client/public/icon-192.png`
- Create: `client/public/icon-512.png`
- Modify: `client/index.html`
- Test: manual browser verification (no automated test framework in `client/`)

**Interfaces:** None — this task has no other task to coordinate with; it's the only task in this plan.

- [ ] **Step 1: Create a temporary HTML source for the icon**

Create a scratch file (anywhere convenient outside the repo's tracked
source — e.g. the session's scratchpad directory, or a temp file in the
repo root that Step 4 deletes before committing) named e.g. `icon-source.html`:

```html
<!DOCTYPE html>
<html>
<head>
<style>
  html, body { margin: 0; padding: 0; background: #333; }
  .icon {
    background: #0C0C0E;
    display: flex;
    align-items: center;
    justify-content: center;
  }
  .icon-512 { width: 512px; height: 512px; }
  .icon-192 { width: 192px; height: 192px; }
  .glyph {
    font-family: 'JetBrains Mono', 'Courier New', monospace;
    font-weight: 700;
    color: #00E5B0;
    line-height: 1;
  }
  .icon-512 .glyph { font-size: 320px; }
  .icon-192 .glyph { font-size: 120px; }
</style>
</head>
<body>
  <div class="icon icon-512" id="icon512"><span class="glyph">&gt;</span></div>
  <div class="icon icon-192" id="icon192"><span class="glyph">&gt;</span></div>
</body>
</html>
```

Both target sizes are laid out side by side in one page so both can be
captured from a single browser session, each scaled proportionally
(`font-size` scales with box size: 320/512 = 120/192 = 0.625) so the two
outputs are visually consistent with each other, not just independently
close.

- [ ] **Step 2: Render and screenshot each element at its exact target size**

Open `icon-source.html` in a browser (a `file://` URL works fine — no dev
server needed for this static page) using the available Playwright
browser tooling. Take an element-scoped screenshot (not a full-page
screenshot) of the `#icon512` element and save it as
`client/public/icon-512.png`; take an element-scoped screenshot of the
`#icon192` element and save it as `client/public/icon-192.png`. Confirm
the saved PNG dimensions actually match (512×512 and 192×192 respectively)
— an element screenshot should already crop to exactly the element's
rendered box, but verify this rather than assuming it, since a
device-pixel-ratio mismatch or accidental full-page capture would produce
the wrong dimensions.

- [ ] **Step 3: Add the missing `<link>` tags to `index.html`**

Find:

```html
    <link rel="manifest" href="/manifest.json" />
```

Replace with:

```html
    <link rel="manifest" href="/manifest.json" />
    <link rel="icon" type="image/png" href="/icon-192.png" />
    <link rel="apple-touch-icon" href="/icon-192.png" />
```

- [ ] **Step 4: Delete the temporary HTML source**

Remove `icon-source.html` (or wherever it was created) — it's a one-time
generation aid, not a tracked project asset. Confirm `git status` shows
only the two new PNGs and the modified `index.html` before committing —
no other file (including this scratch HTML, if it was placed inside the
repo tree) should be staged.

- [ ] **Step 5: Manual verification**

Setup: `cd client && npm run dev` if not already running (reuse an
existing dev server if one is up).

1. Load the app in a browser — confirm the browser tab shows the new
   teal `>` icon (dark background) instead of a generic placeholder.
2. Navigate directly to `http://localhost:<port>/icon-192.png` and
   `http://localhost:<port>/icon-512.png` — confirm both return `200`
   with an actual image (not a 404 page).
3. Check the browser's console/network log during normal app usage —
   confirm the `Failed to load resource: 404 ... icon-192.png` message
   that's shown up throughout this project's manual testing no longer
   appears.
4. Navigate to `http://localhost:<port>/manifest.json` directly and
   confirm it's still valid JSON referencing both icon paths (this file
   isn't changed by this task, just confirming nothing broke it).
5. If the browser/OS supports it, check the "Install app" prompt or
   equivalent — best-effort, not blocking if unavailable in this
   environment — and confirm the icon shown there matches.

- [ ] **Step 6: Commit**

```bash
git add client/public/icon-192.png client/public/icon-512.png client/index.html
git commit -m "Add PWA icon (dark background, teal > glyph matching the login screen)"
```
